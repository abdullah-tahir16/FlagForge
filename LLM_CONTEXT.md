Use this folder and code structure in the new project: keep all source code under src/ split into core/, infrastructure/, and presentation/; put stable domain definitions in core/types/<DomainName>/types.ts with re-exports from core/types/<DomainName>/index.ts; put backend/API integration in infrastructure/api/<DomainName>/index.ts and transport request/response types in infrastructure/api/<DomainName>/types.ts; put one TanStack Query hook or mutation per file in infrastructure/hooks/<DomainName>/use<Operation>.ts; put orchestration logic in infrastructure/useCases/<DomainName>/use<DomainName>UseCase.ts; put thin route wrappers in presentation/containers/<DomainName>/index.tsx; put screen-level UI behavior in presentation/hooks/<DomainName>/use<DomainName>Feature.ts; and put feature UI in presentation/components/<DomainName>/index.tsx, splitting child components into folders like Header/index.tsx, Actions/index.tsx, Form/index.tsx, List/index.tsx, Card/index.tsx, Table/index.tsx, and Modal/index.tsx. Keep React component files to one default-exported arrow component with a Props interface, keep constants in consts.ts, pure helper functions in fns.ts, schemas and static lookup data in data.ts, API files as pure HTTP calls only, hooks as query/mutation wrappers only, use-cases as business orchestration only, containers as render-only wrappers, and presentation hooks as the place for transient UI state, handlers, and derived view data.
